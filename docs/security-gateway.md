# 보안 게이트웨이 설계

- 상태: 구현됨, 기본 꺼짐 (2026-10-21). 켜기 전 평가(8장)는 키를 받은 뒤 한다
- 관련: [위협 모델](threat-model.md) (T41 조회 권한, T42 · T43 · R13 · R14), [기능 13번 보안 게이트웨이](features.md#13-보안-게이트웨이-jev-기본-꺼짐), `services/llm/jev.py`

## 1. 정의

보안 게이트웨이는 LLM Lambda 안에서 **모델(Claude)을 부르기 전과 도구 결과가 모델에게 가기 전**에 서는 판정 층입니다. MCP 서버는 하나 그대로 두고, 게이트웨이가 그 앞에서 다음 네 가지만 합니다.

| | 하는 일 | 누가 정하나 | 감사 관문 |
|:--|:--|:--|:--|
| ① 위협 탐지 | 질문과 도구 결과에 AI에게 내리는 지시가 숨어 있는가 | **Jev** (Claude와 다른 모델) | 유입 |
| ② 도구 라우팅 | 이 질문에 MCP 서버 하나의 도구 중 무엇이 필요한가 | **Jev** | 경계 |
| ③ 권한 확인 | 요청자가 그 도구를 실행할 수 있는가 | **코드** (`tool_access.py`) | 경계 |
| ④ 감사 기록 | ①~③의 판정과 근거를 남긴다 | **코드** (`audit.py`) | 세 관문 모두 |

범위 밖 (게이트웨이가 하지 않지만 그대로 둔다)
- **변경 승인**: 변경 도구는 실행하지 않고 승인 카드를 만들고, 결정자가 인증된 버튼으로 승인해야 MCP가 재확인 뒤 한 번만 실행한다 (`approvals.py`, 실행 관문). 게이트웨이의 탐지가 놓쳐도 AWS가 바뀌지 않게 하는 마지막 장치다
- 가리기(`redaction.py`), 결과 격리(`injection.wrap`), 진단 절차(`diagnose.py`)

## 2. 원칙

1. **판정과 강제를 나눈다.** Jev는 확률을 내고, 막고 거르고 기록하는 것은 코드다. 권한처럼 정답이 정해진 판정(그룹 × 도구 표)은 모델에 맡기지 않는다. 확률 모델이 '허용' 쪽으로 틀리면 일반 사용자가 CloudTrail · IAM을 보게 되기 때문이다
2. **Jev의 출력은 결정을 엄격하게만 만든다.** 거절 · 표시 · 경고를 더할 수는 있지만, 코드가 거절한 것을 허용으로 바꾸거나 승인을 건너뛰게 할 수는 없다 (라우팅도 권한으로 거른 도구 안에서만 고른다)
3. **Jev가 없어도 지금처럼 돈다.** 꺼짐 · 키 없음 · 시간 초과 · 모양이 다른 답이면 Jev 판정을 비우고 지금의 방어(패턴 탐지, 도구 검색, `tool_access`, 승인)로 진행한다. 그 사실을 감사 로그에 남긴다
4. **같은 기록이면 같은 판정을 다시 볼 수 있어야 한다.** Jev 모델 버전을 고정하고(`jev-1.13.0`), 확률과 기준값, 답한 버전을 감사 로그에 남긴다

## 3. 흐름

```text
질문 ──▶ 가리기 ──▶ ① ② Jev 한 번 ─────────────────────────────┐ (물음 여럿을 한 요청에)
                     ├ threat  : 이 질문에 숨은 지시가 있는가        │
                     ├ tool_i  : 이 질문에 도구 i가 필요한가 (볼 수 있는 도구만)
                     └ admin   : 관리자 도구가 필요한가 (일반 사용자만)
                                                                    ▼
          ③ 코드: 권한 확인 ── 라우팅 결과를 볼 수 있는 도구로 거름 ── 위협 판정에 따라 거절 / 표시 / 진행
                                                                    ▼
          Claude ◀─▶ 도구 호출 ── ③ 코드: 이름으로 불러도 권한 없으면 거절, MCP도 다시 확인
                         │
                         ▼ 도구 결과 (가린 글)
                     ① Jev: threat  ── 의심이면 '의심 문구' 표시, 모델에게 경고, 이후 변경 요청에 '의심 뒤 요청'
                         │
                         ▼ 변경 도구면 (게이트웨이 밖)
                     승인 카드 ── 결정자 승인 ── MCP 재확인 ── 실행
④ 모든 판정 ──▶ 감사 로그 (질문 행 · 도구 행 · 변경 작업 행) ──▶ 역추적의 관문 셋 (경계 · 유입 · 실행)
```

## 4. 단계별 설계

### 4.1 질문 분류 (①②, Jev 한 번)

모델을 부르기 전에 가린 질문을 Jev에 한 번 보냅니다. 물음은 모두 noul(0~1 확률)입니다.

| 물음 | 대상 | 기준값 | 코드가 하는 일 |
|:--|:--|:--|:--|
| `threat` | 모든 질문 | 0.9 이상 | 모델을 부르지 않고 거절 안내. 감사 로그의 질문 행에 `gateway.decision = "blocked"` |
| | | 0.5 ~ 0.9 | 진행하되 질문 행에 '의심 질문' 표시. 이 질문에서 나온 변경 요청의 승인 카드에 경고 (지금의 '의심 뒤 요청'과 같은 경고) |
| `tool_i` | 요청자가 볼 수 있는 도구마다 | 0.5 이상, 많아야 8개 | 확률 차례로 시스템 프롬프트 끝(캐시 표시 뒤)에 적어 그 도구부터 찾게 한다. 도구 목록은 바꾸지 않는다 (프롬프트 캐시) |
| `admin` | 일반 사용자만 | 0.9 이상 | 모델을 부르지 않고 '관리자에게 요청' 안내 (#189에 있음) |

- 거절 기준을 높게 두는 이유: 오탐이면 정상 질문이 답을 받지 못한다. 그 아래는 막지 않고 표시만 하며, 변경은 어차피 승인을 거친다
- 라우팅 물음의 도구 설명은 첫 문장만 보낸다 (공식 도구는 설명이 수천 자). 도구 73개면 물음만 약 5천 토큰이라 한도(질문과 물음 합쳐 64k) 안이다
- 의심 질문은 '의심 뒤 요청' 신호의 출처로 적는다(`taintedBy`의 `tool`이 `user_question`). 출처가 질문 자체라 요청 값의 출처(`matchedArgs`)는 생기지 않는다

### 4.2 권한 확인 (③, 코드, 지금 그대로)

`tool_access.py`가 그대로 막습니다. Jev는 여기에 관여하지 않습니다.

1. 모델에게 주는 도구 목록에서 관리자 전용 도구를 뺀다 (도구 검색으로도 못 찾음)
2. 모델이 이름으로 불러도 LLM Lambda가 거절하고 감사 로그에 실패로 남긴다
3. MCP 서버도 관리자 표시(`vigie/role`)가 없으면 관리자 전용 도구를 실행하지 않는다
4. 라우팅(4.1)은 1의 목록 안에서만 묻는다. 그래서 Jev가 무엇을 골라도 볼 수 없는 도구가 시스템 프롬프트에 적히지 않는다

### 4.3 도구 결과 검사 (①, 결과마다 Jev 한 번)

Vigie에서 실제 위협은 질문보다 **도구 결과 속 지시문**(간접 인젝션)입니다. 로그 한 줄, 알람 설명, 문서 본문은 제3자가 씁니다.

- 조회 도구의 결과를 가린 뒤 Jev에 `threat` 하나를 묻는다 (결과물 도구의 결과는 이 서비스가 만든 것이라 묻지 않는다). 길면 2만 자씩 나눠 묻고(앞 5조각까지) 가장 높은 확률을 쓴다
- 결과가 나오는 대로 Jev 검사를 함께 돌리고, 모든 도구가 끝난 뒤 결과마다 판정을 모은다. 그래서 켜면 진행 상황의 '도구 끝남'이 검사만큼 늦고, 감사 로그 도구 행의 걸린 시간에도 기다린 시간이 들어간다(검사 시간은 따로 `gateway.ms`)
- 0.5 이상이면 지금의 패턴 탐지(`injection.scan`)가 찾은 것과 **합친다** (어느 하나라도 의심이면 의심). 종류 이름은 `jev`로 남긴다
- 그 뒤는 지금과 같다: 모델에게 "따르지 마라" 경고를 붙이고, 화면 · 감사 로그에 '의심 문구', 이후 변경 요청에 '의심 뒤 요청'과 승인 카드 경고
- 결과를 버리거나 막지 않는다. 이미 조회한 데이터이고, 막는 장치는 승인이다
- 패턴 탐지는 없애지 않는다: Jev가 꺼져도 남고, 근거 문장(어느 줄이 지시문인지)을 짚는 것은 패턴이 한다

### 4.4 감사 기록 (④, 코드)

| 행 | 더할 필드 |
|:--|:--|
| 질문 | `gateway`: `{model, threat, decision(allowed · flagged · blocked · guided · unavailable), routed[], admin}` |
| 도구 호출 | `injectionSuspected`에 `jev` 종류, `gateway`: `{threat(백분율 정수) \| unavailable, ms}` |
| 변경 작업 | 지금 그대로 (`taintedBy`에 의심 질문 · 의심 결과가 함께 들어간다) |

역추적의 관문 셋은 이렇게 읽습니다.
- **경계**: 등록부에 없는 도구 호출, 권한 없어 거절된 호출 (지금은 앞의 것만)
- **유입**: 의심 질문, 의심 결과(패턴 · Jev), 그 뒤의 변경 요청, 지시문에서 온 요청 값
- **실행**: 지금 그대로 (승인 요청 → 결정 → 실행, 묻지 않은 감시 장치 약화)

## 5. 실패와 대체

| 상황 | 질문 분류 | 도구 결과 검사 | 기록 |
|:--|:--|:--|:--|
| 꺼짐 (`JEV` 없음) · 키 없음 | 하지 않음. 도구 검색으로 찾고, 권한은 그대로 | 패턴 탐지만 | `gateway` 필드 없음 (꺼져 있음) |
| 시간 초과 (2초) · 오류 · 모양이 다른 답 | 위와 같음 | 위와 같음 | `unavailable`과 이유 |
| Jev가 틀림 (위협을 놓침) | 진행 | 패턴이 잡으면 의심 | 역추적의 유입이 '탐지된 것 없음'. 변경은 승인이 막는다 |
| Jev가 틀림 (정상을 위협으로) | 0.9 이상이면 거절 | 의심 표시 (막지 않음) | `blocked` · `jev` 종류로 남아 오탐을 셀 수 있다 |

## 6. 밖으로 나가는 데이터

- 나가는 것: 가린 질문(Claude에 보내는 것과 같은 글), 가린 도구 결과, 볼 수 있는 도구의 이름 · 설명 첫 문장
- 나가지 않는 것: 비밀 값, 이전 대화, 요청자 신원 · 그룹 (권한은 코드가 정하므로 Jev가 알 필요가 없다)
- 가리기는 패턴이라 리소스 이름 · IP 같은 값은 그대로 나간다 (R6). TypeSafe는 미국에 있고 데이터 보관 정책이 공개되지 않았으며 자체 설치가 없다 (R14). **켜기 전에 데이터 처리 조건을 확인한다**
- 키: SSM SecureString `/vigie/<env>/TYPESAFE_API_KEY` (LLM 역할은 이미 `/vigie/<env>/*`를 읽는다)

## 7. 지연과 비용

- 질문마다 Jev 한 번(위협 · 라우팅 · 관리자 필요를 한 요청에), 도구 결과마다 한 번
- 회사가 밝힌 지연은 70~500ms, 독립 측정은 없다. 질문 분류는 모델 호출 앞에 서므로 2초에서 끊는다. 도구 결과 검사는 여러 결과를 함께 보낸다 (도구를 함께 부르는 것처럼 스레드로)
- 가격은 입력 백만 토큰당 $0.042, 출력 무료(공개 가격). 도구 정의 5천 토큰 + 질문, 결과 몇 천 토큰이면 질문 하나에 1센트의 수십분의 1 수준이다. 실제 값은 평가(8)에서 잰다

## 8. 켜기 전 평가

Jev의 인젝션 탐지와 라우팅 정확도는 독립 검증이 없습니다. 아래를 재서 기준을 넘을 때만 켭니다.

| 평가 | 데이터 | 재는 것 | 켜는 기준 (제안) |
|:--|:--|:--|:--|
| 위협 탐지 (도구 결과) | 공격 말뭉치: `tests/test_injection.py`의 공격 문구, `local/`의 장애 재현 지시문, 다른 말로 바꾼 것(영문 · 전각 괄호 · 줄 분할 · 지시 없이 값만 심은 것). 정상: AWS 문서 · 실제 로그 | 재현율, 오탐률 | 패턴 탐지보다 재현율이 높고, 정상 문서 오탐률 5% 이하 |
| 위협 탐지 (질문) | 운영 질문(`scripts/measure_tool_search.py`의 21개 등)과 공격 질문 | 0.9 이상 거절된 정상 질문 수 | 정상 질문 거절 0건 |
| 라우팅 | `measure_tool_search.py`의 평가 질문 21개 (정답 도구가 적혀 있다) | 고른 도구에 정답이 든 비율, 도구 검색 횟수 | 지금(도구 검색만)보다 첫 도구 정확도가 높을 것 |

- 평가는 실제 API를 부르므로 키가 생긴 뒤 하고, 비용은 위 가격으로 미리 계산해 알린다
- 지시문 없이 값만 심은 공격(종목 코드 · 로그 그룹 이름만 바꿔 둔 문서)은 '숨은 지시'가 없어 위협 탐지로는 원래 잡기 어렵다. 이것은 요청 값의 출처(유입 관문의 실패)와 승인이 맡는다

## 10. 열린 질문

- Jev API의 실제 요청 · 응답 형식과 인증 머리 (지금은 공개 SDK 설명에서 옮긴 것)
- TypeSafe의 데이터 보관 · 학습 사용 조건
- 기준값(0.5 · 0.9)은 평가 결과로 다시 정한다
- 질문 위협 0.5~0.9 구간에서 승인 카드 경고만으로 충분한지, 결정자 외 한 사람 더 보게 할지
